# The Hive, Inc. — Design Spec

- **Date:** 2026-09-22
- **Status:** Approved in brainstorming, pending written-spec review
- **Owner:** Ramsy J (product, testing, art via Higgsfield) + Claude (engineering)

---

## 1. Summary

The Hive, Inc. is a commercial, portrait-mode mobile idle/incremental game about building a beekeeping empire. It follows the proven mechanical structure of the idle-farm genre (the reference title is Egg, Inc.). Players release bees into hives, the bees make honey, a delivery fleet ships the honey for cash, and players reinvest in hives, fleet and research. They unlock more valuable honey tiers and periodically "Swarm" (prestige) for a permanent earnings bonus.

**Originality rule (legal):** game mechanics and rules are not protected by copyright. Expression is: art, names, text, UI layout, number tables and audiovisual style. Every name, piece of flavor text, balance number, screen layout and art asset in The Hive, Inc. is our own. We do not copy the reference game's tables, research names, UI screens, currency names or art. Higgsfield prompts must not reference the reference game or use its screenshots.

## 2. Goals and success criteria

| Goal | Success criterion |
|---|---|
| Ship a commercial v1.0 on Google Play | Public soft launch around day 30 (≈ 2026-10-22) |
| Earn revenue from day 1 | Rewarded ads live at launch; in-app purchases live, or following in v1.1 under the fallback |
| Retain players | Pacing targets met (§5.9); day-1 retention measured in analytics |
| Tunable economy | All balance values in data files, overridable remotely without a new build |
| No lost purchases or progress | Server-verified purchases, cloud save, restore on reinstall |

**Non-goals for v1.0:** contracts, co-op, the contract-only multiplier currency, artifacts/expeditions, leaderboards, subscription, interstitial ads, iOS build, localization beyond English.

- **Timeline:** 1 month to public soft launch.

## 4. Architecture

Four layers. Each layer depends only on the layers below it.

```
Presentation (Godot scenes/UI)
    │ reads state, dispatches player actions
Simulation (pure GDScript, no Nodes)
    │ reads definitions
Data (JSON balance files + Remote Config overrides)

Services (interfaces + fake/real implementations):
  SaveService · AuthService · AdsService · IAPService
  AnalyticsService · RemoteConfigService · ClockService · CrashService
```

### 4.1 Project layout

```
game/                         # Godot project root
  project.godot
  data/                       # balance JSON (source of truth)
    honey_tiers.json  hives.json  vehicles.json  research.json
    epic_research.json  boosts.json  products.json  pests.json
    milestones.json  daily_gift.json  config.json
  src/
    sim/                      # pure simulation, no scene tree access
      game_state.gd           # the complete serializable player state
      economy.gd              # derived rates: production, shipping, income
      tick.gd                 # advance(state, dt)
      offline.gd              # catch-up for elapsed time
      prestige.gd             # swarm payout + reset
      actions.gd              # buy_hive, buy_vehicle, research, etc.
      bignum_format.gd        # number display formatting
    services/
      interfaces/             # abstract service contracts
      fake/                   # in-memory fakes for editor/tests
      real/                   # AdMob, Play Billing, Firebase REST, Sentry
    ui/                       # scenes + scripts per screen/panel
    autoload/                 # Game (state owner), Events (signal bus), Services (locator)
  assets/                     # art/audio (placeholders until Higgsfield art lands)
  locale/en.csv               # every player-facing string
  tests/                      # GUT unit tests
firebase/
  functions/                  # Cloud Functions (TypeScript): verifyPurchase, serverTime
  firestore.rules
docs/
```

### 4.2 Key decisions

- **The simulation doesn't depend on screens.** `sim/` never touches Nodes. `advance(state, dt)` is deterministic, so offline catch-up and "8 hours later" tests run in milliseconds.
- **Number handling:** 64-bit floats (up to about 1e308), which covers 12 tiers with a wide margin. Display suffixes: K, M, B, T, then our own sequence (aa, ab, ac …). A big-number library can be swapped in later behind `bignum_format.gd` if needed.
- **The game tick** runs on `_process` in the `Game` autoload at a fixed 10 Hz simulation step. UI reads the state and redraws when an `Events.state_changed` signal fires.
- **Service locator** (`Services` autoload): a fake or real implementation is chosen at startup. The editor and tests always use fakes. Android builds use the real ones.
- **Data overrides:** at boot, bundled JSON loads first, then Remote Config values are merged over it by key path (for example `honey_tiers.3.value`).

## 5. Core loop and economy

### 5.1 Main formula

```
honey_rate     = bees × honey_per_bee_per_sec × production_multipliers
ship_rate      = Σ vehicle capacity/sec × fleet_multipliers
income_per_sec = min(honey_rate, ship_rate) × honey_value(tier)
                 × research_value_mult × (1 + 0.08 × legacy_pollen × pollen_bonus_mult)
                 × buzz_bonus × active_boost_mults
```

Honey above `ship_rate` is wasted. The HUD capacity bar turns green → amber → red as `honey_rate / ship_rate` goes past 80% and then 100%.

### 5.2 Release button and bees

- Holding **Release** adds bees at `release_rate` bees/sec (base 4/sec, raised by research) until total hive capacity is reached.
- Each released bee is shown as a pooled sprite flying from the Brood Comb to a hive. The animation is capped (at most 30 visible at once) and is only for show.

### 5.3 Buzz Bonus

- While Release is held, `buzz` rises toward 1.0 over 5 s and decays over 10 s after release.
- `buzz_bonus = 1 + buzz × buzz_strength` (base strength 0.5, raised by epic research).

### 5.4 Hives

- 4 plots. The first plot starts with a Skep; the others are empty.
- 12 tiers, upgraded in place: Skep, Log Hive, Box Hive, Stacked Hive, Hive Tower, Honey Barn, Apiary Hall, Comb Dome, Glass Hive, Sky Hive, Orbital Hive, Hive Nexus.
- `hives.json` sets capacity and cost per tier. Starting curve: capacity ×≈3.2 per tier, cost ×≈12 per tier. Final values are set during tuning.

### 5.5 Fleet

- 10 tiers: Wheelbarrow, Bike Cart, Pickup, Box Truck, Tanker, Semi, Cargo Train, Airship, Cargo Jet, Teleport Pod.
- 3 slots at the start, raised to 12 by research. Upgraded in place per slot.
- `vehicles.json` sets capacity and cost per tier.

### 5.6 Queen's Brood (auto-hatch)

- Unlocked by research. Adds `brood_rate` bees/min per occupied hive plot, up to capacity.
- Keeps running offline while honey stores last.

### 5.7 Honey Stores (offline)

- Each store = 1 hour of offline time (raised by epic research).
- Standard: up to 3 stores at a 60% offline income rate. Pro Permit: up to 8 stores at 100%.
- Offline catch-up: `elapsed = min(now − last_seen, stores × store_hours)`, simulated by `offline.gd` in coarse steps (up to 60 steps).
- `now` comes from `ClockService`. When online it uses the Firebase server time; offline it uses device time with sanity checks (time going backwards means 0 elapsed; a jump beyond the cap is clamped).

### 5.8 Honey tiers

12 tiers, each worth about ×4 the last (tunable):

| # | Honey | Flavor direction |
|---|---|---|
| 1 | Wildflower | Cozy, real |
| 2 | Clover | Cozy, real |
| 3 | Orange Blossom | Cozy, real |
| 4 | Manuka | Premium, real |
| 5 | Royal Jelly | Premium, real |
| 6 | Medicinal Nectar | Science begins |
| 7 | Biofuel Honey | Industrial |
| 8 | Crystal Honey | Uncanny |
| 9 | Nano-Honey | Sci-fi |
| 10 | Plasma Nectar | Sci-fi |
| 11 | Quantum Nectar | Wild |
| 12 | Stellar Honey | Cosmic |

- **Colony Value (CV)** = a weighted mix of the current income rate, bee count and brood output. Its formula lives in `economy.gd`, with the weights in `config.json`.
- Reaching `unlock_cv` for tier n+1 shows **Upgrade Honey**. Upgrading resets hives, fleet, bees, research, cash and stores, and keeps everything that Swarm keeps.
- The highest tier reached is saved permanently (for the Swarm screen and analytics).

### 5.9 Research (common)

- About 40 items in 8 tiers, bought with cash. Tier k unlocks after `tier_unlock[k]` total purchases.
- Categories: honey value, honey per bee, hive capacity, release rate, brood rate (including the unlock), fleet capacity, fleet slots, and cost reductions (hive, vehicle).
- Each item has `max_level`, `base_cost`, `cost_growth` and `effect_per_level`. Effects in the same category multiply together.
- All common research resets on Swarm and on honey-tier upgrade.

### 5.10 Pacing targets (written as simulation tests using a scripted "reasonable player" bot)

| Milestone | Target (active play, no boosts, 0 pollen) |
|---|---|
| First hive upgrade | < 1 min |
| First vehicle upgrade | < 3 min |
| Honey tier 2 | ≈ 10 min |
| First sensible Swarm (≥ 5 pollen) | ≈ 2–3 h |
| Stellar Honey | several weeks across many Swarms |

## 6. Meta-progression

### 6.1 Swarm (prestige)

- Available once the projected payout is ≥ 1 Legacy Pollen.
- **Payout:** `pollen_gained = floor(k × E^0.2)`, where E = cash earned during the current run (since the last Swarm) and k is in `config.json`. Each run is scored on its own earnings, and the payout grows more slowly than earnings do.
- **Reset:** bees, hives, fleet, stores, common research, cash and honey tier (back to Wildflower).
- **Kept:** Legacy Pollen, Golden Nectar, epic research, Pro Permit, Honey Jar level and contents, milestones, daily-gift progress and unused boosts.
- **Bonus:** each pollen gives +8% income (multiplied by the epic item "Pollen Potency").
- The Swarm screen shows the live projected gain and a before/after income comparison.

### 6.2 Golden Nectar (premium currency)

- **Sources:** pests, rewarded ads, the daily gift, milestones, Honey Jar, IAP.
- **Sinks:** epic research, boosts.

### 6.3 Epic Research (12 items, permanent, bought with Golden Nectar)

Offline Rate+, Store Duration+, Research Discount, Hive Discount, Fleet Discount, Pest Frequency+, Boost Duration+, Head Start (starting cash), Pollen Potency, Brood Rate+, Buzz Strength+, Pest Reward+.

### 6.4 Boosts

- **Slots:** 2 active (4 with Pro Permit). The same boost type refreshes its duration instead of taking a second slot.
- **Types:**
  - Income ×2 (30 min)
  - Income ×5 (30 min)
  - Income ×2 (2 h)
  - Brood ×10 (10 min)
  - Instant Cash (a fraction of CV)
  - Store Doubler (×2 store hours for the next offline period)
- **Ad Boost:** income ×2 for 1 hour per ad, stackable up to 4 hours. It takes no slot.

### 6.5 Pests

- **Wasp:** a straight path across the screen, spawning about every 30 s (Poisson, tunable). A tap pays cash (75%) or Golden Nectar (25%).
- **Hornet:** about 1 in 12 spawns, on a fast curved path. Better rewards, and can be tripled with an ad.
- Cash rewards = fraction × CV. Nectar rewards come from a weighted table in `pests.json`.

### 6.6 Other systems

- **Welcome Back:** shown when offline earnings are > 0. Buttons: **Collect**, or **Watch Ad → ×2**.
- **Daily Gift:** a 7-day repeating cycle. Missing a day pauses the cycle rather than resetting it. Rewards are in `daily_gift.json`.
- **Milestones:** lifetime bees-released goals (1K, 10K, 100K … 1B), each paying Golden Nectar.

## 7. Monetization

### 7.1 Rewarded ads (AdMob)

- **Placements:**
  - Ad Boost
  - Welcome Back ×2
  - Free Nectar (30-minute cooldown)
  - Hornet ×3
- **Limits:** a daily cap per placement, stored in the save with a reset at the server day.
- **Consent:** GDPR and US-state consent through Google UMP before ads load.
- **Never:** no interstitial or banner ads in v1.

### 7.2 In-app purchases (Google Play Billing)

| Product ID | Type | Price (tunable) | Grant |
|---|---|---|---|
| `nectar_pack_1` … `nectar_pack_5` | Consumable | $0.99 / 4.99 / 9.99 / 19.99 / 49.99 | Golden Nectar, with better value in bigger packs |
| `pro_permit` | Non-consumable | $4.99 | 8 stores, 100% offline rate, 4 boost slots, a special hive skin |
| `honey_jar` | Consumable | $4.99 | Grants the jar's contents, raises its level, resets its contents |

### 7.3 Honey Jar (piggy bank)

- Every purchase made with cash (hive, vehicle, research) adds Golden Nectar to the jar, up to the jar's cap.
- Level L sets the cap and a crack bonus: `cap(L)` and `bonus(L)` are in `config.json`, and both grow with each crack.
- The UI shows current contents, cap, bonus and price.

### 7.4 Purchase flow

```
Client buys → Play returns purchaseToken
→ client calls Cloud Function verifyPurchase(productId, token)
→ function checks with the Google Play Developer API
→ function writes the grant into users/{uid}/save (transaction, token recorded for idempotency)
→ client pulls the save → function acknowledges (non-consumable) or consumes (consumable)
```

- Pending or failed purchases grant nothing.
- On startup, the client asks Play for owned purchases and re-runs verification for any not yet granted (restore and recovery).

## 8. Backend (Firebase)

- **Plan:** Blaze (pay-as-you-go), needed for Cloud Functions. Expected cost at soft-launch scale is about $0.
- **Auth:** anonymous by default. An optional **Link Google account** in Settings; Apple added with iOS.
- **Firestore:** `users/{uid}` holds one document, `save`, with a versioned JSON state (`schema_version`) plus `updated_at` (server timestamp).
  - **Autosave:** every 60 s and when the app is backgrounded. The local file is always written first.
  - **Conflicts:** the newer `updated_at` wins. If the two saves differ a lot (lifetime earnings > 10× apart), a "Keep which save?" prompt appears.
- **Security rules:** a user can only read and write their own document. Fields holding premium grants (`nectar_purchased`, `pro_permit`, `processed_tokens`) can only be written by Cloud Functions.
- **Cloud Functions (TypeScript):** `verifyPurchase` and `serverTime`.
- **Remote Config:** balance overrides and a `min_supported_version`.
- **Analytics:** a thin Android plugin wrapping the Firebase Analytics SDK, falling back to the GA4 Measurement Protocol.
  - **Events:** `tutorial_step`, `tier_reached`, `swarm`, `ad_watched{placement}`, `purchase{product}`, `session_start`, `pest_tapped`.
- **Crashes:** Sentry Godot SDK (free tier).
- **Godot integration:** Firebase is called over REST (Auth, Firestore, Functions, Remote Config) with an HTTP client wrapper, so no native plugin is needed for those.

**Save schema, forward-compatible:** the save includes empty containers for `contracts`, `prophecy`, `artifacts` so v1.2+ features can be added without breaking migrations. `schema_version` drives a list of migration functions.

## 10. Error handling

- **Network down:** the game stays fully playable offline. Cloud sync, Remote Config and the server clock retry with backoff. Purchases and ads show "Needs connection".
- **Purchase errors:** a failed verification keeps the token in a pending list and retries on the next startup. The user sees a neutral "Purchase processing" message and is never double-granted (idempotency by token).
- **Ad not loaded:** the button is disabled with a "No ad available, try again soon" tooltip. No reward is granted without the reward callback.
- **Corrupt local save:** the last good backup is kept (rotating 2 files), then the cloud copy is tried.
- **Clock tampering:** backwards time = 0 elapsed. Offline time is always capped by stores.
- **Remote Config errors:** bundled defaults are used. A malformed override key is logged to Sentry and ignored.

## 11. Testing

- **GUT unit tests** for all of `sim/`: formulas, cost curves, tick, offline catch-up equivalence (offline result ≈ stepping online, within tolerance), Swarm payout/reset/keep lists, save round-trip and migrations, and the pacing-target bot (§5.10).
- **Service fakes** let UI flows (purchase, ad reward, sync conflict) be exercised in tests and in the editor.
- **Cloud Functions tests** with the Firebase emulator (verifyPurchase idempotency, security rules).
- **Debug menu** (debug builds only): time-skip, grant currencies, reset save, force pest, toggle fake services.
- **Device QA:** real Android phones, with license-tester accounts for test purchases and AdMob test ad units. Closed-test feedback goes through a Google Form linked in Settings.

## 13. Risks

| Risk | Mitigation |
|---|---|
| The Play review for production access takes longer than 7 days | Start the closed test by day 9; keep the build stable during review |
| Godot mobile plugins (AdMob, Billing) break on the current Godot version | Test the plugins in week 1 with a throwaway spike; pin plugin and engine versions |
| Inconsistent AI art | Style guide plus reference sheet; a consistent seed and prompt template; placeholders let the game ship even if art lags |
| Economy too fast or slow | Pacing bot tests, plus Remote Config tuning during the closed test |
| Scope creep | Non-goals list (§2) is binding for v1.0 |
